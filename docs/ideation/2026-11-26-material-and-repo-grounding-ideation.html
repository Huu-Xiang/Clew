CE Ideation · Clew Codebase Grounded

让 Clew 支持源码库与学习资料（以研读 Milvus 源码为例）

日期：2026-11-26 候选：14 个原始创意 → 淘汰 8 个 → 留存 6 个 覆盖维度：4 / 4 轴
现状基线（代码实证）
  • backend/app/models/domain.py:30：主题的 ResourceLink 目前只是书签 URL，AI 不会抓取、不会索引，也不能挂本地源码目录或 PDF。
  • backend/app/agent/runtime.py:253：对话只挂了 OpenAI 的 web_search（只能搜公开网页），context.py:36 明确禁止模型读取本地文件系统。
  • backend/app/mcp_server/server.py：Clew 目前只是只读 MCP Server（给外部工具读图谱），本身还不能连接 DeepWiki MCP 等外部资料源。
  • 外部成熟实践（2025–2026）：DeepWiki / DeepWiki MCP、基于 Tree-sitter/AST 的本地代码知识图谱（CPG）、以及 Graph-Anchored RAG（把知识点直接锚定到 file:line）。
主题拆解维度（4 Axes）
1. 资料挂载与只读探索图谱/主题如何绑定本地代码库或文档，让 AI 安全只读检索。
2. 仓库一键生成学习图谱把大型源码库（如 Milvus）转成按依赖分层的学习路线图。
3. 源码锚定教学与测验讲解、笔记、结业测验全部引用真实 file:line 与代码片段。
4. 外部生态桥接复用 DeepWiki MCP / 本地编码 Agent，而非重造一个 IDE。
留存排序方案（Top 6 Survivors）
1图谱绑定只读「本地源码库 / 资料目录」+ 沙箱只读工具套件
Axis 1: 资料挂载与只读探索Conf: HighCx: M

允许每个图谱绑定 1 个或多个只读资料源（本地 Git 仓库目录如 ~/Dev/milvus，或 Markdown/PDF 资料文件夹），同时给 Clew Agent 新增 3 个严格只读、路径限制在绑定根目录内的原生工具：list_source_tree、search_source（ripgrep/关键词/符号搜索）、read_source_slice（按行号片段读取）。

依据 (Basis)direct: Clew 已有成熟的 Responses API 原生工具循环（tools.py），新增只读工具零破坏架构，且完全保留“不静默改图谱”的铁律。
取舍 (Tradeoffs)最直接解决“聊 Milvus 时 AI 瞎编源码”的痛点，且不依赖向量库；缺点是需要本地先 git clone 或放好资料目录。
2主题级「源码锚点（Code Anchors）」与基于真实代码的结业测验
Axis 3: 源码锚定教学与测验Conf: HighCx: M

把主题的 ResourceLink 扩展出 code_anchor 类型（如 internal/querynodev2/segments/segment.go:120-210 + 函数/结构体名）。点击主题弹窗可直接预览代码片段；发起结业测验（Closure Quiz）时，后端自动把该主题锚定的真实源码切片塞进出题上下文，出的题直接考真实调用链和边界条件（例如“为什么 Milvus 这里要用 RLock 而不是 Lock”），不再是泛泛八股文。

依据 (Basis)direct: runtime.py:153 的 generate_closure_quiz 已经支持只读工具，把 read_source_slice 开放给测验生成轮次即可闭环；external: KG-RAG 实证表明锚定源码能大幅降低教学幻觉。
取舍 (Tradeoffs)让 Clew 从“通用 AI 问答”质变为“真正能验收源码理解度的学习工具”；缺点是源码版本更新后行号可能漂移（可通过符号名辅助定位缓解）。
3仓库架构扫描 → 一键提案「分层源码研读图谱」（Repo-to-Graph Bootstrap）
Axis 2: 仓库一键生成学习图谱Conf: HighCx: M

新建图谱时新增「从代码库导入（Import from Codebase）」入口：本地确定性脚本先扫描目录树、go.mod/package.json、README、核心包依赖（轻量化 AST/import 图），把精炼的仓库骨架交给模型，通过现有 propose_ingest 生成按「入口层 → 核心协调层（RootCoord/DataCoord/QueryCoord）→ 存储引擎（Knowhere/Segment）」分 Zone 且带先修边的学习图谱提案，每个节点自动带上关键文件路径。

依据 (Basis)direct: 复用现有 Obsidian 导入弹窗与 propose_ingest 审阅流；external: 参考 DeepWiki / CodeGraph 先抽确定性结构再让 LLM 归纳的范式，token 消耗可控。
取舍 (Tradeoffs)彻底解决“面对几十万行 Milvus 不知道从哪读起”的冷启动难题；缺点是不同语言（Go/C++/Python/Rust）的 import 解析需要循序覆盖。
4接入 DeepWiki MCP / 外部 MCP 客户端：免克隆直接读 GitHub 开源大库
Axis 4: 外部生态桥接Conf: MedCx: M

让 Clew 后端作为一个轻量 MCP Client，优先支持免配置的 DeepWiki MCP（输入 milvus-io/milvus 即可查架构文档、提问、拿源码引用）以及用户自定义本地 MCP（如 Context7、本地知识库）。无需在本地 clone 几个 GB 的源码，就能在 Clew 里直接建图谱、学源码。

依据 (Basis)external: DeepWiki 已预索引 50,000+ 开源库并提供官方 MCP 接口；direct: Clew 后端依赖里已有 mcp Python SDK（backend/app/mcp_server/server.py:20）。
取舍 (Tradeoffs)对开源公开库零门槛、极低成本；缺点是不支持私有仓库或你本地魔改过的分支，适合与方案 1 互补。
5「执行链路追踪模式（Trace-to-Path）」：沿着一条请求链长出学习子图
Axis 2: 仓库一键生成学习图谱Conf: MedCx: M

读 Milvus 这类分布式系统，按目录学容易迷失，真正有效的是按一条真实请求链路（如「一次 Vector Search 请求如何从 Proxy → QueryCoord → QueryNode → Knowhere 返回」）。用户给一个入口函数或场景，AI 通过只读代码搜索一路追踪调用链，把沿途关键模块抽成一条线性/分支子图提案（用 requires / bridges 串联），顺手把每一步的核心代码行记进节点。

依据 (Basis)reasoned: 分布式系统源码研读的核心心智模型是数据流/控制流而非静态文件夹树；direct: 完美复用 Clew 现有的 propose_expand 和方向边可视化。
取舍 (Tradeoffs)学习体验极爽、直击面试与架构理解核心；缺点是强依赖方案 1 的只读代码搜索精度。
6通用「本地资料库（PDF / 论文 / 网页快照）」分块索引与引用
Axis 1: 资料挂载与只读探索Conf: MedCx: L

在代码库之外，允许把 PDF 论文（如 Milvus SIGMOD 论文、HNSW 论文）、设计文档 Markdown 拖入图谱资料夹；本地轻量抽取文本与章节标题（SQLite FTS5 全文索引，无需重型向量库），AI 对话和提炼总结时用 search_materials 检索段落并附带页码/章节引用。

依据 (Basis)direct: Clew 已自带 SQLite，内置 FTS5 即可实现零外部依赖的精准关键词/章节检索，符合本地优先定位。
取舍 (Tradeoffs)把 Clew 从“源码学习”泛化到“论文/教材/源码混合学习”；缺点是 PDF 版面解析（公式/表格）边角情况较多，适合作为第二阶段。
淘汰清单与理由（Rejected Candidates — 8 Cut）
被淘汰想法淘汰原因
内置完整向量数据库做全库 Embedding RAGtoo expensive / heavy：在桌面端内嵌 Milvus/Chroma + 向量化管线维护成本极高，且对代码结构（调用链/符号）检索效果反不如 ripgrep + AST/FTS5。
把 Clew 改造成带代码编辑器的 AI IDEsubject-replacement：违背 Clew 核心定位（graph-first learning workspace），重造 VS Code/Cursor 毫无优势。
全自动把仓库里每个函数都生成一个图谱节点not actionable / graph explosion：Milvus 有数万个函数，1:1 映射会让 2D/3D 图谱彻底炸裂且失去“可测验学习单元”的意义。
直接开放不受限的 Shell 命令给模型执行unsafe / violates Clew boundary：违背 context.py:36 的安全与显式契约边界，只读沙箱工具已能覆盖 95% 源码阅读需求。
把整本 PDF 或整个目录原文直接塞进 System Promptunscalable：大仓库/多篇论文必然超上下文上限并暴涨 ChatGPT 额度消耗。
仅支持手动把代码复制到聊天框already covered / below ambition floor：现在本来就能复制粘贴，没有解决“主动认识仓库和资料”的核心痛点。
只做 GitHub URL 网页抓取（无 API/MCP）fragile：GitHub 页面限流且大库目录深，稳定性远不如本地只读挂载（方案 1）或 DeepWiki MCP（方案 4）。
自动监控 git commit 实时重写整个学习图谱violates invariant：静默变更图谱违背 Clew 铁律，且频繁改动会打断学习节奏。
