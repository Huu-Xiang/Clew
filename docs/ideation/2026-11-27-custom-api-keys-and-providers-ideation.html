思考维度（Topic Axes）

1. 接入架构与协议层如何在不破坏现有 ChatGPT OAuth 的前提下，用最小抽象同时覆盖 Anthropic 与主流 OpenAI 兼容服务。
2. 密钥安全与入口解耦如何安全保管 Key、去掉强制 ChatGPT 登录门槛，并让配置体验像填写一张“连接卡片”一样简单。
3. 跨模型会话与能力对齐切模型后旧对话不报错，不同厂商缺失联网搜索/思考强度时如何显式告知而非静默失败。
4. 学习场景下的多模型协同聊天讲解、提炼总结、结课测验各自适合什么模型，怎么让 BYOK 既好用又省钱。

在 agent_transcripts 里额外记录一条 provider_protocol 标记（例如 openai_responses / anthropic_messages / openai_chat）。当用户在同一段学习对话里中途从 ChatGPT 切到 Claude（或反过来）时，后端检测到协议不一致，自动跳过旧协议的私有 transcript，走 runtime.py:233-241 现成的 fresh=True 路径，从标准 chat_messages（含已应用的提案/提炼/测验记录）干净地重建上下文继续聊。

被淘汰的想法（Rejection Summary）

# 候选想法 淘汰原因
1 引入独立 LiteLLM Proxy（Docker + Postgres/Redis）作为统一网关 对本地桌面/单机运行的 Clew 过重，违背“轻量开箱即用”定位，增加大量运维和排错成本。
2 只靠 Anthropic 的 OpenAI 兼容端点，不写原生 Anthropic 适配器 虽然代码少 80 行，但会丢掉 Prompt Caching（对每轮携带图谱上下文的 Clew 成本影响极大）以及原生 Extended Thinking / 稳定工具调用。
3 前端直连 Anthropic / OpenAI API（浏览器存 Key 在 localStorage） 存在严重安全隐患（XSS 泄露 Key）、CORS 限制，且绕开了 Clew 后端的工具执行、图谱校验与快照审计边界。
4 直接把 API Key 明文存在 SQLite 或 workspace JSON 里 违背 Clew 现有 KeyringCredentialStore 的无明文落盘安全基线，导出备份或排错时极易意外泄露密钥。
5 自动静默 Fallback（比如 Claude 限流时偷偷切到 GPT 或便宜模型） 明确违反 AGENTS.md 原则（"Do not add hidden semantic routing or silent fallback behavior"），也会让 BYOK 用户在不知情下产生意外账单。
6 引入全量 LangChain / LlamaIndex 框架重写 AgentRuntime Clew 现有 runtime.py 仅 426 行且与 SQLite 事件流、暂停问答卡片、撤回机制深度契合，引入重框架反而破坏可控性与调试透明度。
